## 🧠 Me, in one screen
我更像“把业务交付变成工程资产”的那类开发：  
- 功能写完不是结束，我会追问：**指标有没有变好？风险边界有没有写清？下次能不能更快？**
- 我偏好把经验变成可复用：**脚手架 / SDK / 规范 / 模板 / 自动化**
- 我的日常关键词：**稳定性、权限治理、安全通信、性能基线、复盘闭环**

---

## 🧩 My default mode
- **先对齐边界**：目标 / 约束 / 风险 / 验收口径（能写成文档就不靠口口相传）
- **先立指标再动手**：性能基线、缺陷口径、响应—修复耗时、回归范围
- **交付要可复用**：把一次性需求抽成模块/SDK/脚手架/规范
- **最后做闭环**：监控 → 复盘 → 规则沉淀 → 自动化（减少“同类问题二刷”）

---

## 🧱 What I build a lot
- **权限与治理**：RBAC、动态路由、菜单/按钮级权限、字典中心、通用 CRUD 方案
- **安全通信**：握手建链、会话密钥、签名验签、nonce/timestamp 防重放（前后端一致）
- **工程体验**：脚手架、lint/CI、依赖治理、代码生成、发布流程、错误归一与可观测性
- **AI 工具化**：把 AI 用在“提效与规范化产物”上（结构化总结/模板化输出/自动化文档）
